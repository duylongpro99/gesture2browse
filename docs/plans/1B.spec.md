# 1B — Perception pipeline — spec (validated design)

Milestone **1B** (roadmap §4.2). Components: `apps/extension/entrypoints/offscreen`, `packages/gesture-core` (extends `packages/protocol` `GestureFrame` additively; offline training in `scripts/train/`). Produced by `obra-brainstorming`; owner decisions batched and answered 2026-09-07 (all option **a**, recorded in `docs/sdd/1B/driver.json`).

## 1. What 1B adds (and what it does not)

1A shipped the vertical slice: an offscreen frame pump (`MediaStreamTrackProcessor` → worker → `HandLandmarker`), a per-frame `GestureFrame` composed from **pure** `gesture-core` pieces (`normalize → 1€ (pointer only) → features → KnnClassifier` placeholder), the `Paused/Armed.{Idle,Scrolling}` FSM, and the offscreen→SW→content-script scroll path. The classifier is a `KnnClassifier` placeholder that returns `none` for every frame, so no real gesture fires end to end yet.

1B makes perception real:
- a **trained MLP classifier** (offline-trained, weights shipped, loaded in the worker) that emits the frozen `GestureLabel` vocabulary with a mandatory `none` class;
- a **palm-facing gate** and a **3-frame vote** so transient/edge poses do not fire;
- **1€ filtering extended** to landmarks 0, 4, 8, 9 (not only the pointer), per arch §3.1;
- **worker robustness**: timed delegate selection (WebGL→WASM by first-inference cost), `webglcontextlost` recovery, adaptive 30/15 fps, and offscreen **restart on stream end**;
- a **golden replay suite** that fails loudly when a threshold or the shipped weights change.

**Out of scope for 1B (owner Q1, option a):** the ONNX-Web inference path. 1B plans the **browser-inference path only**. G1 is GO at 30 fps (M1 + agent) and the WebGL→WASM delegate fallback is existing architecture. The final G8 browser-inference-vs-ONNX-Web GO/NO-GO is **owner sign-off deferred until G3 lands**; the ONNX-Web fallback is a **roadmap §9 re-plan trigger** ("Intel Air < 20 fps on every path"), not a 1B component. "Delegate order" is treated as a fixture/bench tunable, not plan material.

Also out of scope: in-browser retraining UI (Phase 3, track 3.1); the pinch/dwell click FSM and snapping (1C); any content-script or dispatcher change.

## 2. Placement (five-question Q1)

Two owning components, joined by one `protocol` message:
- **`apps/extension/entrypoints/offscreen`** owns the worker lifecycle, delegate selection/recovery, adaptive fps, restart-on-stream-end, and the per-frame composition that writes the `GestureFrame` (including the new `palmFacing` field and the trained classifier's label/score).
- **`packages/gesture-core`** owns the pure classifier (`MlpClassifier` behind the existing `Classifier` interface, `KnnClassifier` retained as the conformance fallback), the pure `palmFacing` geometric helper, the extended 1€ landmark filtering as pure functions, and — because **all** gesture timing/gating lives in the FSM (CLAUDE.md §2) — the 3-frame vote and palm-facing gating inside the XState machine.
- The **message that joins them** is `GestureFrame` in `packages/protocol`, extended additively (§5).

Single-owner boundary tension resolved: arch §3.1 lists "3-frame vote, palm-facing gate" under the *offscreen classifier* step, but CLAUDE.md §2 / `.claude/rules/offscreen.md` forbid gesture-timing logic in the offscreen document and name the FSM as the single owner of timing, hysteresis, cooldowns and confidence gating. **CLAUDE.md wins:** the per-frame *palm-facing boolean* is a geometric feature computed offscreen (no timing) and carried on `GestureFrame`; the *3-frame vote* and the *gate that blocks firing* live in the `gesture-core` FSM. This is noted in the plan `## Status`.

## 3. Offline MLP classifier and training (owner Q2, option a)

- **Model.** A small multilayer perceptron: input = 63 wrist-centred, scale-normalized landmark coordinates (the output of the existing `normalizeLandmarks`); one hidden layer (ReLU); softmax over the 8 `GestureLabel` classes, **`none` mandatory**. Pure-TS forward pass so training and runtime share it; no new runtime dependency (matches tech-stack §6 "avoids" and keeps `gesture-core` pure).
- **Runtime** (`gesture-core`): `MlpClassifier implements Classifier` — constructed from a weights object, `classify(input: number[]) → { label, score }` where `score` is the softmax probability of the winning class. `KnnClassifier` stays as the interface-conformance fallback (used when no weights are present, e.g. a clean checkout before training, and by tests).
- **Weights artifact.** Serialized JSON (layer shapes + weight/bias arrays + the label order + a feature-version tag) shipped as a web-accessible resource at `models/gesture-mlp.json`, resolved by the offscreen document from the extension origin exactly like `models/hand_landmarker.task` today, and loaded into the worker at startup. The worker falls back to `KnnClassifier`/`none` if the artifact is missing or fails to parse (never throws the pump).
- **Training script** (`scripts/train/`, Node 24 built-in TS, camera-free): reads `fixtures/gestures/**` `FixtureRecord`s, extracts normalized-landmark feature vectors, splits **held-out by `subjectId`** (subject-independent evaluation), trains by SGD (gradients in the script; forward via the shared `gesture-core` MLP), writes `models/gesture-mlp.json`, and prints a **per-gesture precision/recall table + false-fires/10 min** using N-frame voting — the G4 artifact.
- **Palm-facing gate.** Pure geometric helper in `gesture-core` (`palmFacing(landmarks): boolean`) from the palm plane normal relative to the camera axis; computed per frame offscreen and written to `GestureFrame.palmFacing`.

**Mock caveat (owner Q3).** G4 is the MOCK test row: no real fixtures or precision/recall targets are collected. We proceed to build and wire the full pipeline against `fixtures/gestures/**` (currently only `placeholder.json`). Exit **E1** ("precision/recall table meets the G4 target ≥ 95 %") **cannot pass mechanically without real fixtures** and is therefore **owner-verified / deferred**; the training script and its table are still built and run, so E1 becomes a one-line owner confirmation once real recordings land.

## 4. Gesture vocabulary (owner Q3, option a)

The classifier's output vocabulary **is** the frozen `GestureLabel` enum (`none, Closed_Fist, Open_Palm, Pointing_Up, Thumb_Down, Thumb_Up, Victory, ILoveYou`). The MOCK role-names are **FSM/Intent mappings, not classifier labels**: `palm-arm`/`open-hand-pause` → `Open_Palm` (the clutch already toggles Armed↔Paused), `fist-scroll` → `Closed_Fist`, `point` → `Pointing_Up`, `pinch-select` → **not a label** (pinch is the geometric feature already derived in `features.ts` and gated by hysteresis in the FSM, 1C's concern), `none` → `none`. **No new protocol labels; no `GestureFrame` label-set change** (CLAUDE.md §4, no synonyms).

## 5. Interface change (five-question Q3)

`GestureFrame` gains one **optional, additive** field in `packages/protocol/src/gesture-frame.ts`:

```ts
palmFacing: z.boolean().optional(), // palm-facing gate result (perception → FSM/diagnostics); absent = ungated
```

This is the "classifier output field" the roadmap names. It is additive: the frozen v0 contract (`gestureframe-v0.contract.test.ts`, non-strict `z.object`) still parses, and 1A's rule "1B/1C/1D/2A extend, none redefines" is honoured. Existing `gesture`/`score` continue to carry the classifier label/confidence; per-class score vectors stay **out** of the steady-state payload (diagnostics can derive them; arch §8 keeps the payload lean). `gesture-core`'s internal `FrameInput` gains an optional `palmFacing?: boolean` consumed by the FSM guards.

**Backward-compatible gating.** The FSM blocks a gesture from firing only on an **explicit `palmFacing === false`**; `undefined` (older frames, and the frozen `1C-fsm-state-tree` contract's frames) is treated as ungated and passes. The 3-frame vote likewise preserves that contract (its scripted holds exceed 3 consecutive frames). Neither frozen contract test is edited.

## 6. Delegate, recovery, adaptive fps (worker robustness)

- **Timed delegate selection.** Keep the existing WebGL→WASM order, but decide by *cost*, not only by init throwing: if WebGL init exceeds a tunable budget or the first inference exceeds a tunable per-frame budget, fall back to WASM and cache the choice (arch §3.1: "init > 5 s or per-frame > 40 ms → CPU"; the numbers are tunables).
- **`webglcontextlost` recovery.** On context loss, recreate the `HandLandmarker`; if WebGL cannot be recreated, fall back to WASM. The pump keeps reading frames; a single failed detect never stalls it (already true in the worker loop).
- **Adaptive fps.** Drop to 15 fps when no hand has been seen for a tunable idle window (5 s); resume 30 fps on detection. Implemented by skipping detects/frames in the worker read loop (the camera still delivers 30 fps; we throttle inference), reported in `PumpStat.fps`.
- **Restart on stream end.** When the transferred stream ends (camera unplugged/tab-close race/track ended), the offscreen document tears down the worker and re-acquires `getUserMedia`, re-running the SW camera pre-check gate. Single-instance is already enforced by the SW (`browser.offscreen.hasDocument()` before `createDocument`, the `getContexts` equivalent).

## 7. Testing (five-question Q5)

- **Fixture replay is the regression suite** (`.claude/rules/gesture-core.md`, roadmap "fixture-first"): every threshold/weights change replays `fixtures/gestures/**`.
- **Classifier P/R** — the training script prints the per-gesture precision/recall + false-fires/10 min table on held-out subjects (E1, owner-deferred on mock).
- **Golden replay suite** (E2) — a `gesture-core` test replays fixtures through `normalize → MlpClassifier → FSM` and asserts a frozen golden (labels/intents) plus a threshold/weights lock, so any change fails loudly.
- **Jitter/lag metrics** — a `gesture-core` test asserts the extended 1€ filtering reduces per-frame landmark jitter on a replayed fixture without excess lag.
- **Adaptive fps e2e** (E3) — Playwright with a fake camera asserts the pump reports ~30 fps with a hand present and downshifts toward ~15 fps when idle; a companion e2e (or the same) simulates context loss via `WEBGL_lose_context` and asserts recovery.
- **Palm-facing / vote unit tests** — pure `gesture-core` tests for `palmFacing` and the FSM's vote+gate, including the backward-compatibility (undefined passes, explicit false blocks) that protects the frozen contracts.

## 8. Principle check (five-question Q4)

- **Two loops, two speeds** — inference stays worker-side; only the numeric `GestureFrame` crosses. Adaptive fps protects the fast loop's CPU budget.
- **Video stays in one process** — landmarks/`VideoFrame` never leave the worker; the weights artifact is numeric only; `palmFacing` is a boolean. `.claude/rules/offscreen.md` and boundary-lint hold.
- **Page is hostile** — unchanged; the SW still validates every `GestureFrame` with the Zod schema before feeding the FSM.
- **Agent proposes, human disposes** — not touched by 1B.
- **Replaceable parts** — the `Classifier` interface is the seam; `MlpClassifier` swaps in behind it, `KnnClassifier` remains the fallback; the ONNX-Web path can later replace the worker's inference behind the same `GestureFrame` output without touching consumers.

## 9. Deviations

None. No `any`/`@ts-ignore`, no new runtime dependency (pure-TS MLP), no new top-level directory (`scripts/train/` is under the allowed `scripts/`). No ADR required. The arch §3.1-vs-CLAUDE.md §2 vote/gate placement is resolved in favour of CLAUDE.md §2 (§2 above) and is a clarification, not a deviation.
