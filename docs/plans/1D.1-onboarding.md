# 1D.1 — First-run onboarding — plan

Milestone 1D.1 (roadmap §4.4). New full-tab first-run wizard that takes a developer-preview
user from install to "I can point and click" with informed consent, in the fewest steps:
consent/privacy → camera-grant handoff (0C) → profile (default Accessibility) → "you're
ready." Design and depth: [`1D.1-onboarding.spec.md`](./1D.1-onboarding.spec.md); tasks:
[`1D.1-onboarding.impl.md`](./1D.1-onboarding.impl.md).

Plan inputs (roadmap §4.4 + §8): 0C grant page (G2, `CameraGrantStatus`); owner intent
(session -1: consent-first with the "video never leaves the device" differentiator; grant
handoff steering to "Allow on every visit"; profile default Accessibility; "you're ready"
→ cheat sheet; the four required unhappy paths; no inline tutorial/calibration).

## The five questions (`CLAUDE.md §1`)

**1. Placement.** Cross-component, joined by `packages/protocol`. Owners: **new**
`apps/extension/entrypoints/onboarding/**` (the wizard page); `background.ts` (first-run
trigger on `onInstalled`; route to onboarding instead of the pump while onboarding is
incomplete; read `Settings.profile` and feed the dispatcher); `packages/protocol` (the
shapes). Joining messages: **`Settings`** (page→`storage.sync`→SW action-mapper),
**`OnboardingState`** (page↔`storage.local`↔SW gate), **`OnboardingComplete`** (page→SW),
and the reused **`CameraGrantStatus`** (grant page→`storage.session`→onboarding page). The
side panel (arch §3.4) stays the steady-state UI; onboarding is the one-time surface that
ends by pointing at it (surface decision D1 in the spec — a new full-tab entrypoint,
following the 1D.5/diagnostics precedent and the full-tab `grant-camera` it hands off to).

**2. Boundary check.** New `.claude/rules/onboarding.md` (header-glob form, like
`grant-camera.md`/`diagnostics.md`): may depend on React, `@gesture/protocol`,
`wxt/browser` (`storage` local+sync / `runtime` / `tabs` / `permissions`),
`navigator.mediaDevices.enumerateDevices` + `navigator.permissions` (readouts only), DOM;
**never** `getUserMedia`, render/retain video/`VideoFrame`/`ImageBitmap`, network, secrets,
gesture-timing logic or constants, `confirm()`, direct `zod`; Zod-validates every stored
blob. `background.md`: reading a non-secret `Settings` from `storage.sync` is allowed (the
"never" is *secrets* in `local/sync`); every inbound message (`OnboardingComplete`)
Zod-validated; selecting a profile is control-plane policy, not gesture timing.
`protocol.md`: additive, `zod`-only, names from arch §6/§3.2. No deviation, no ADR needed.

**3. Interfaces touched.** All additive, protocol-first (Task 1): new `Profile`
(`accessibility`|`standard`|`presenter`, default `accessibility` — promotes the informal
`dispatcher.ts` union), `Settings` (`{ profile }`, `chrome.storage.sync`), `OnboardingState`
(`{ completed, completedAt?, version }`, `chrome.storage.local`), `OnboardingComplete`
(page→SW envelope). `CameraGrantStatus` reused unchanged. No frozen 1A/1B/1C member
redefined; `Settings` is designed for 1D.2/1D.3 to extend additively.

**4. Principle check (`docs/02-architecture.md §1`).** *Two loops two speeds* — onboarding
is human-pace UI reading storage snapshots; the hot path is untouched. *Video stays in one
process* (**most at risk**) — the onboarding page never calls `getUserMedia` and renders no
video; capture and the grant stay in `grant-camera` (0C); onboarding reads only device
*kind* and permission *state*. *Page is hostile* — every stored blob is re-validated with
its Zod schema before use, even blobs our own pages wrote. *Agent proposes / human disposes*
— n/a (no agent in onboarding). *Replaceable parts* — the page is a pure consumer of
`protocol` shapes and owns no timing constant; background only *selects* a profile.

**5. Tests.** Per-task unit tests (schemas; pure `steps.ts`; pure background gate/profile
helpers); two frozen consumer-side contract tests (below); Playwright e2e (fake webcam) for
the two roadmap Exit criteria plus the four required unhappy paths and the keyboard/aria
path. No gesture-timing constant changes, so no fixture replay is required.
