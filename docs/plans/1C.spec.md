# 1C — Page plane and actions — Spec (validated design)

Milestone 1C (`docs/05-roadmap.md §4.3`). Builds on the 1A frozen seam (`GestureFrame`, `Intent`, `PageCommand`, `PageEvent`, `TransitionLogEntry`, FSM `Paused`/`Armed.{Idle,Scrolling}`, `PortName`). Plan inputs (roadmap §8): 1A merged; **G5** dispatch default = CDP (2026-09-05); **G6 (MOCK)** snapping ON / initial snap radius 40 px / pinch default / dwell 600 ms Accessibility (2026-09-12).

This spec answers the five questions (`docs/plans/README.md`); the architecture plan restates them in `1C.md`, the tasks + code are in `1C.impl.md`.

Owner decisions (2026-09-12 handoff, all as recommended):
- **Q1 dispatch default = A.** Prefer CDP whenever the `debugger` permission is granted; content-script synthetic is the automatic fallback when not. Onboarding/settings offers the trusted-click grant. Attach CDP per gesture-session while armed, detach on pause.
- **Q2 pointer plane = A.** Route pointer as `PageCommand{type:'pointer',x,y,state}` over the existing frozen SW→content port, one message/frame. Direct offscreen→CS port stays reserved. **ADR 0001** (proposed) records the arch §3.2 deviation (MV3 `MessagePort`-transfer limit). Execute proceeds only after the owner accepts the ADR at PR review.
- **Q3 bindings = A.** Build Action executors for back/forward, tab-switch, zoom; bind swipe-left→back / swipe-right→forward as the Standard-profile default (swipe off in Accessibility); tab-switch and zoom ship dispatcher-capable with **no** default gesture binding in 1C (bound later in 1D.3).

## 1. Purpose and scope

Make the page controllable by the pointer plane: a cursor overlay the user can see, an index of interactable elements it snaps to, the full gesture state machine that turns held/pinched/swiped hands into discrete `Intent`s, and a dispatcher that executes them as trusted (CDP) or synthetic (fallback) input plus browser navigation. Exit is the Fitts page hitting the `roadmap §4.6` acquisition-time and click-precision targets, the XState model tests passing, and the service worker recovering after a kill.

**In scope:** cursor overlay, interactable index + snapping (`page-index`), full `Armed.*` FSM with hold timers/cooldowns/hysteresis (`gesture-core`), dispatcher (CDP-when-granted with synthetic fallback, scroll inertia, back/forward via swipe, tab/zoom executors), pointer relay, service-worker hardening (port reconnect, SPA re-injection).

**Out of scope (later milestones):** rich a11y snapshot extraction and agent use of it (2A — 1C only *freezes the id scheme* and the `snapshot` request/response shape and answers it from the interactable index); gesture-map editor and tab/zoom gesture bindings (1D.3); calibration sliders for the tunables (1D.2); HUD announcements (1D.4); the direct offscreen→CS pointer port (reserved, ADR 0001 exit condition).

## 2. Placement (five-question Q1)

Three owning components joined by `packages/protocol` messages, plus one library. One owner each:

- **`packages/page-index`** (rule `page-index.md`, jsdom-testable, no `chrome.*`/React): the interactable index (grid-bucketed spatial index, `MutationObserver`, visibility filter, iframe geometry) and the snapping algorithm (speed-scaled radius, neighbour hysteresis, pointer latch). Produces the numeric **interactable id scheme** — stable per page load, shared with the 2A a11y snapshot ("click element 17").
- **`packages/gesture-core`** (rule `gesture-core.md`, pure TS, XState): the full `Armed.*` state tree (`Idle`, `Pointing`, `PinchDown`, `Dragging`, `Scrolling`, `SwipeArmed`, `Hold`) with all hold timers, cooldowns, pinch hysteresis, the 300 ms stable-tracking gate, and dwell timing. Emits `Click`/`DragStart`/`DragEnd`/`Swipe`/`HoldGesture` intents. **Sole owner of gesture timing** (CLAUDE.md §2).
- **`apps/extension/entrypoints/content`** (rule `content.md`, hostile page, Shadow DOM, no `chrome.*`/secrets): cursor overlay (closed shadow root, rAF interpolation), wiring the page-index snapping to the pointer, answering `snapshot`, drawing `highlight`/`preview`, and the synthetic **fallback** click/drag/focus path.
- **`apps/extension/entrypoints/background`** (rule `background.md`, control plane, `chrome.*`/`chrome.debugger`): the dispatcher (Intent→trusted CDP input or synthetic fallback), CDP attach/detach lifecycle, pointer relay (`GestureFrame.pointer`→`PageCommand.pointer`), hover merge into the FSM, scroll inertia, back/forward/tab/zoom executors, and hardening (port reconnect, SPA re-injection).

Joining messages (`protocol`): `PageCommand` (SW→CS: pointer/highlight/preview/snapshot/fallbackClick added), `PageEvent` (CS→SW: hover/snapshot added), `A11yItem` (new; the frozen id scheme), `Intent` (internal gesture-core→SW: Click/DragStart/DragEnd/Swipe/HoldGesture added). `CursorState` (new enum) rides in `PageCommand.pointer`.

## 3. Interfaces (five-question Q3) — `protocol` first, then both sides

All additive; nothing frozen by 1A is redefined (roadmap §2.1).

```ts
// NEW enum — cursor render states (arch §3.3), carried in PageCommand.pointer
type CursorState = 'idle' | 'pointing' | 'snapped' | 'pinch' | 'drag' | 'paused';

// NEW — the interactable id scheme, frozen here, shared with 2A's a11y snapshot.
// id: number, stable per page load; bbox = [x, y, w, h] in CSS px (viewport).
interface A11yItem { id: number; role: string; name: string; value?: string;
                     bbox: [number, number, number, number]; state?: string[] }

// PageCommand (SW → CS): 1A `scroll` frozen; 1C ADDS:
//   { type:'pointer';  x:number; y:number; state:CursorState }   // ADR 0001
//   { type:'highlight'; ids:number[]; label?:string }
//   { type:'preview';   id:number; label:string }
//   { type:'snapshot' }                                          // request
//   { type:'fallbackClick'; id:number }                          // synthetic path

// PageEvent (CS → SW): 1A `ready` frozen; 1C ADDS:
//   { type:'hover';    id:number|null; bbox?:[number,number,number,number] }
//   { type:'snapshot'; items:A11yItem[] }                        // response

// Intent (gesture-core → SW): 1A Arm|Pause|Scroll frozen; 1C ADDS:
//   { type:'Click';      id:number }        // pinch-tap or dwell on snapped id
//   { type:'DragStart';  id:number }
//   { type:'DragEnd' }
//   { type:'Swipe';      dir:'left'|'right' }
//   { type:'HoldGesture'; kind:'Victory'|'Thumb_Up'|'Thumb_Down'|'ILoveYou' }
```

- `Click.id`/`DragStart.id` carry the snapped interactable id, so the dispatcher clicks the element's box (not raw coordinates — G5 caveat). The id is resolved by the FSM from the current hover target (see §4).
- `HoldGesture` is emitted by the `Armed.Hold` state so 2A can attach `Agent.Proposing`/`AwaitingConfirm`; 1C has only a placeholder consumer (PRD: "Victory reserved for a placeholder panel").
- **No `Action` protocol type here** — `Action`/`Proposal` are 2A's to fix (roadmap §5.1). 1C's back/forward/tab/zoom executors are internal dispatcher functions, not protocol shapes.

## 4. Data flow

### 4.1 Pointer plane + snapping (per frame)
```
offscreen → GestureFrame{pointer,...} → SW (already every frame, for the FSM)
SW dispatcher → PageCommand{pointer,x,y,state} → active tab's content port   [ADR 0001]
content → page-index.snap(x,y) → {id,center} → cursor overlay renders `snapped`
content → PageEvent{hover,id,bbox} → SW
SW merges hover.id into the FSM FrameInput (so Click/dwell carry the right id)
```
`state` in `PageCommand.pointer` is derived by the SW from the FSM state (idle/pointing/pinch/drag/paused) combined with whether content last reported a hover (`snapped`).

### 4.2 Click (pinch-tap and dwell)
```
Pinch: Pointing --pinch<in--> PinchDown --pinch>out within tap_max--> emit Click{hoverId}
Dwell (Accessibility default): pointer stable within dwell_radius over the same hoverId
       for dwell_ms → emit Click{hoverId}
SW: if debugger granted → CDP Input.dispatchMouseEvent at the element box centre
                          (scroll-into-view first, G5 caveat)
    else → PageCommand{fallbackClick,id} → content synthetic pointer/mouse/click + focus()
```
Pointer is latched at pinch-in (arch §5 "pointer freeze during pinch") so the click lands where the user aimed.

### 4.3 Drag, scroll, swipe-nav
```
PinchDown held > tap_max → emit DragStart{hoverId}; pinch>out → emit DragEnd
  → CDP mouse press/move/release (trusted) or synthetic fallback
Closed_Fist + vy → emit Scroll{dy} (1A) → PageCommand{scroll} + inertia decay in the dispatcher
SwipeArmed + lateral velocity → emit Swipe{dir}; Standard profile maps
  left→history.back, right→history.forward (chrome APIs); Accessibility profile: swipe off
```

### 4.4 CDP lifecycle + hardening
CDP attaches once per gesture-session on `Arm` (while armed), detaches on `Pause`/disconnect. On `chrome.debugger.onDetach` or a kill, the dispatcher falls back to synthetic and re-attaches on the next `Arm`. The service worker is stateless (arch §3.2): the content port map and CDP attach state rebuild from `chrome.storage.session` + `onConnect`; SPA route changes re-inject the content script and the content re-sends `ready`.

## 5. Error handling (page is hostile; SW is stateless)
- Content validates **every** `PageCommand` with the Zod schema before acting; unknown/invalid commands are ignored (never `eval`'d).
- SW validates **every** `PageEvent` with the Zod schema before acting.
- CDP unavailable (permission not granted, `onDetach`, attach failure) → automatic synthetic fallback; never a dead click.
- Snapping over a stale index (element removed between index build and click) → the dispatcher re-resolves the box at dispatch time; a missing element aborts the click quietly.
- SW idle-out / kill → `onConnect`/`onDisconnect` + `storage.session` restore; e2e asserts recovery.

## 6. Principles (five-question Q4, `02-architecture §1`)
- **Two loops, two speeds** — 1C is entirely the fast perception–control loop; no agent, no network.
- **Video stays in one process** — 1C touches no video; only `GestureFrame` (no landmarks) enters the SW, and only `PageCommand`/`PageEvent` cross to the page.
- **The page is hostile** — content holds no secrets/authority, runs only SW-sent, Zod-validated `PageCommand`s; CDP (trusted input) and all policy live in the SW.
- **Agent proposes / human disposes** — n/a to direct control, but 1C fixes the `HoldGesture` intents and the a11y id scheme that 2A's confirm/observe path needs.
- **Replaceable parts** — index, snapping, FSM, dispatcher, and the CDP-vs-synthetic executor sit behind protocol messages / small interfaces.

## 7. Tests (five-question Q5)
- **FSM fixture replay + XState model tests** (`gesture-core`): scripted `FrameInput` sequences → expected `Intent` sequences and no false fires, for pinch-tap, dwell, drag, swipe, hold, and the stable-tracking gate / cooldowns. Threshold changes replay the suite (`fixtures/gestures/`).
- **Snapping property tests** (`page-index`, jsdom): dense/overlapping DOM fixtures; hysteresis never flickers between neighbours; speed-scaled radius; id stability per page load.
- **Cursor overlay** (`content`, happy-dom + Playwright screenshots): five/six `CursorState` renders, closed shadow root, `aria-hidden`.
- **Dispatcher** (Playwright test page): counts trusted (CDP) vs synthetic clicks; confirms box+scroll-into-view targeting.
- **Fitts e2e** (Playwright, fake camera): scripted `GestureFrame` pointer path acquires 40 px targets; asserts median acquisition ≤ 1.8 s and click precision ≥ 95 % (roadmap §4.6).
- **SW-kill recovery e2e** (Playwright): kill the service worker, assert the pointer/click path recovers.
- **Contract tests** (frozen with the plan, one per interface fixed here, written from 2A's side): `PageCommand`, `PageEvent`, `A11yItem`, `Intent`, FSM full state tree.

## 8. Tunables (not plan material — `roadmap §2.1`, `03-tech-stack §4`)
Named here, valued by fixture replay / owner tuning (G6 MOCK defaults in parentheses; realified later): snap radius (40 px, ON), snap speed-scale, neighbour hysteresis margin, pinch in/out (0.25/0.35×dist(0,9)), pinch release debounce (100 ms), tap max (300 ms), dwell time (600 ms, Accessibility default) + dwell radius, hold gesture times (600 ms Victory / 700–800 ms Thumbs / 1000 ms palm), stable-tracking gate (300 ms), cooldowns (800 ms swipe / 1 s hold), swipe velocity/distance, scroll inertia decay, pointer gain. All live in `gesture-core/constants.ts` (FSM timing) or `page-index` (spatial), the single owners; 1D.2/1D.3 expose the sliders.
