# 1D.5 — Diagnostics screen — implementation plan

Bite-sized tasks with code, derived from `1D.5-diagnostics.spec.md`. Run the
five-question checklist (`docs/plans/README.md`) against this file before executing;
it is answered in `1D.5-diagnostics.md`. TDD per task: the failing test comes first
(`obra-test-driven-development`); `gesture-core` threshold changes would need a
fixture replay, but this milestone changes no timing constant.

## Global Constraints

Owning `.claude/rules/<component>.md` files, treated as compile errors:

- `.claude/rules/protocol.md` — additive Zod shapes only; depends on `zod` only.
- `.claude/rules/offscreen.md` — no `chrome.storage`, no network, no gesture-timing
  logic; landmarks leave only under the diagnostics recording exception.
- `.claude/rules/background.md` — validate every inbound message with Zod; diagnostic
  state in `storage.session` is allowed (not a secret).
- `.claude/rules/gesture-core.md` — pure TS; no DOM/`chrome.*`/`fetch`/timers; public
  API via `exports` only.
- **new** `.claude/rules/diagnostics.md` — the diagnostics page (this milestone adds
  it; see Task 6). A changed/added boundary ships its rule file in the same PR
  (`CLAUDE.md §5`).

Repo-wide: TS strict, no `any`/`@ts-ignore` without an ADR; no new runtime dependency
(none is introduced here); packages export only via `package.json` `exports`.

Interfaces are frozen protocol-first in **Task 1**; every later task consumes them.
Additive only — no frozen 1A/1B/1C member is redefined.

## Task 1 — Protocol: diagnostics shapes (additive)

Add the diagnostics shapes and extend `PumpStat` additively. This is the
interfaces-first task; the three consumer-side contract tests (frozen in this plan
session under `## Exit checks`) begin to pass here.

- `StageTimings = {captureMs, inferMs, normalizeMs, classifyMs, filterMs}` (all
  `z.number()`), names echoing `BenchRow`.
- `PumpStatSchema` **+=** `stages: StageTimingsSchema.optional()`, `dropped:
  z.number().int().nonnegative().optional()` — optional so every 0B producer stays
  valid.
- `FrameSampleSchema = {ts, present, gesture: GestureLabel.optional(), score,
  pinch: z.number().optional(), velocity:{vx,vy}}` — features only, no landmarks.
- `FalsePositiveEntrySchema = {ts, eventTs, note: z.string().optional(),
  transition: TransitionLogEntrySchema.optional(), frameWindow:
  z.array(FrameSampleSchema), landmarkWindow: z.array(FixtureFrameSchema).optional()}`.
- `DiagnosticsConfigSchema = {recordLandmarks: z.boolean()}`.
- `DiagnosticsExportSchema = {schema: z.literal('gesture-diagnostics/v0'),
  exportedAt: z.string(), fps: z.array(PumpStatSchema), transitions:
  z.array(TransitionLogEntrySchema), falsePositives:
  z.array(FalsePositiveEntrySchema), config: DiagnosticsConfigSchema}`.

**Files:**
- Create: `packages/protocol/src/diagnostics.ts`
- Modify: `packages/protocol/src/pump.ts` (additive `stages`/`dropped`),
  `packages/protocol/src/index.ts` (export `./diagnostics.js`)
- Test: `packages/protocol/test/diagnostics.test.ts` (schema round-trips;
  `PumpStat` without `stages`/`dropped` still parses — additive proof)
- Makes pass (do not edit): `packages/protocol/test/contracts/1E-pumpstat-stages.contract.test.ts`,
  `packages/protocol/test/contracts/1E-false-positive.contract.test.ts`

## Task 2 — Offscreen: emit per-stage timings + dropped-frame count

Time each stage in the inference worker (capture/draw, `detectForVideo`, normalize,
classify, filter) with `performance.now()` deltas, and count frames the reader drops
(stream backpressure / `shouldInfer` skips) within the fps window. Aggregate with a
pure, unit-testable accumulator (no globals, mirroring `fps-logger.ts`). Fold the
result into the `PumpStat` the offscreen document already posts to the SW. Measurement
only — no gesture-timing logic (that stays in `gesture-core`).

**Files:**
- Create: `apps/extension/entrypoints/offscreen/stage-timer.ts` (pure: feed per-stage
  marks, read median-per-stage over the window; `dropped` counter)
- Modify: `apps/extension/entrypoints/offscreen/inference.worker.ts` (measure stages,
  count drops, add `stages`/`dropped` to the `stat`/`frame` path),
  `apps/extension/entrypoints/offscreen/main.ts` (carry `stages`/`dropped` onto the
  posted `PumpStat`)
- Test: `apps/extension/test/stage-timer.test.ts`

## Task 3 — Offscreen: rolling landmark buffer (record-landmarks, default OFF)

A pure ring buffer of the last N frames' raw landmarks. An intra-document
`{type:'record'; on:boolean}` message (relayed from the SW) arms/disarms it. While
armed, the worker includes `landmarks` on the emitted `GestureFrame` (the schema's
existing `landmarks?` "only when recording" field); disarmed, steady state is
unchanged (no landmarks cross the Port). The offscreen document never persists —
the SW owns storage.

**Files:**
- Create: `apps/extension/entrypoints/offscreen/landmark-buffer.ts` (pure ring buffer)
- Modify: `apps/extension/entrypoints/offscreen/inference.worker.ts` (populate
  `landmarks` when armed), `apps/extension/entrypoints/offscreen/main.ts` (handle the
  record arm/disarm relayed from the SW)
- Test: `apps/extension/test/landmark-buffer.test.ts`

## Task 4 — Service worker: feature window, false-positive builder, record relay

Keep a bounded rolling window of recent `GestureFrame` **features** (a `FrameSample`
ring — cheap, over frames the SW already receives) and, when landmarks are present,
their `FixtureFrame` form. On a `FlagFalsePositive` runtime message, build a
`FalsePositiveEntry` (last transition + the feature window + the landmark window when
present) and append it to a bounded `storage.session` series. Persist the extended
`PumpStat` (already recorded — just carries the new fields). Relay a
`SetRecordLandmarks` message to the offscreen document (Task 3) and persist
`DiagnosticsConfig`. All inbound messages validated with Zod.

**Files:**
- Create: `apps/extension/entrypoints/background/diagnostics.ts` (pure: `FrameSample`
  ring, `FixtureFrame` window, `buildFalsePositive(...)`, bounded-series append)
- Modify: `apps/extension/entrypoints/background.ts` (feed the ring from the frame
  consumer; handle `FlagFalsePositive` / `SetRecordLandmarks`; persist config +
  entries)
- Test: `apps/extension/test/diagnostics-sw.test.ts`

## Task 5 — gesture-core: DiagnosticsExport → replay conversion

Pure helpers mapping the export/its entries into the existing replay inputs:
`framesFromDiagnostics(entry): FrameInput[]` (from `frameWindow`, FSM-level replay via
`replayFrames`) and `fixtureFromDiagnostics(entry): FixtureRecord | null` (from
`landmarkWindow` when present, full-pipeline replay via `replayFixtureWith`; `null`
otherwise). Exported from the package public API.

**Files:**
- Create: `packages/gesture-core/src/diagnostics-replay.ts`
- Modify: `packages/gesture-core/src/index.ts` (export the two helpers)
- Test: (unit) `packages/gesture-core/test/diagnostics-replay.test.ts`
- Makes pass (do not edit):
  `packages/gesture-core/test/contracts/1E-diagnostics-export-replay.contract.test.ts`

## Task 6 — Diagnostics page (new entrypoint) + rule file

A full-tab entrypoint modeled on `grant-camera` (auto-discovered by WXT; no
`wxt.config.ts` change). React page that: reads `pumpSeries`/`transitionSeries`/the
false-positive series/`DiagnosticsConfig` from `storage.session` (validated with Zod)
and subscribes to `chrome.storage.onChanged`; renders fps, per-stage timings,
dropped-frame count, the live gesture/intent/transition stream, and the
false-positive list; a *flag as false positive* control (sends `FlagFalsePositive`);
a record-landmarks toggle (sends `SetRecordLandmarks`); and a JSON **Export** button
that builds a `DiagnosticsExport` (pure builder) and downloads it. Renders landmark
**points** only if present — never raw video. Ship `.claude/rules/diagnostics.md`
(depends: React, `protocol`, `chrome.storage`/`runtime`/`tabs`; never: raw video,
network, secrets, gesture-timing constants, `confirm()`; validates stored blobs with
Zod).

**Files:**
- Create: `apps/extension/entrypoints/diagnostics/index.html`,
  `apps/extension/entrypoints/diagnostics/main.tsx`,
  `apps/extension/entrypoints/diagnostics/App.tsx`,
  `apps/extension/entrypoints/diagnostics/export.ts` (pure: storage snapshot →
  `DiagnosticsExport`), `apps/extension/entrypoints/diagnostics/view.ts` (pure
  formatters for the readouts), `.claude/rules/diagnostics.md`
- Test: `apps/extension/test/diagnostics-export.test.ts`,
  `apps/extension/test/diagnostics-view.test.ts`
