# 1D.1 — First-run onboarding — implementation plan

Tasks for milestone 1D.1. Design: [`1D.1-onboarding.spec.md`](./1D.1-onboarding.spec.md);
five-question form + Exit checks: [`1D.1-onboarding.md`](./1D.1-onboarding.md). Written by
`obra-writing-plans` (session 0). Each task is one commit
(`[{component}] task {N}: {title}`); every task lists exact `Create:`/`Modify:`/`Test:`
paths (the next sessions' write scope is derived from these).

## Global Constraints

- **Owning rule files** (treat as compile errors, `CLAUDE.md §2`):
  `.claude/rules/onboarding.md` (**new**, created in Task 3), `.claude/rules/background.md`,
  `.claude/rules/protocol.md`. Full-tab-page precedent: `.claude/rules/grant-camera.md`,
  `.claude/rules/diagnostics.md`.
- **Protocol-first** (`CLAUDE.md §1` Q3): the shapes land in `packages/protocol` (Task 1)
  before either side uses them. All additive; no frozen 1A/1B/1C member redefined.
- **Video stays in one process** (arch §1/§6): the onboarding page never calls
  `getUserMedia`, never renders or retains video/`VideoFrame`/`ImageBitmap`. Camera capture
  and the grant stay in `grant-camera` (0C); onboarding reads only device *kind*
  (`enumerateDevices`) and permission *state* (`permissions.query` / stored
  `CameraGrantStatus`).
- **Single timing owner** (`CLAUDE.md §2`): no gesture-timing logic or constant enters the
  onboarding page or the background profile wiring. Background *selects* a `Profile`; every
  threshold/dwell constant stays in `gesture-core`.
- **Page is hostile to its own blobs** (arch §1): every value read from
  `chrome.storage.sync`/`local`/`session` is re-validated with its `protocol` Zod schema
  before use. The onboarding page never imports `zod` directly — it validates through the
  schemas re-exported by `@gesture/protocol`.
- **No `confirm()`**, no network calls, no secrets in storage (`CLAUDE.md §2`,
  boundary-lint). TypeScript strict; no `any`/`@ts-ignore` without an ADR; packages via
  `package.json` `exports` only.
- No new runtime dependency (React, `zod`, `wxt` already in `docs/03-tech-stack.md`); no new
  top-level directory.

## Task 1 — protocol: `Profile`, `Settings`, `OnboardingState`, `OnboardingComplete`

Add the shared shapes, additive and `zod`-only. `Profile` promotes the informal
`background/dispatcher.ts` union to a protocol enum (default `accessibility`). `Settings`
is the minimal user-preference record (extended additively by 1D.2/1D.3). `OnboardingState`
is the device-local first-run record. `OnboardingComplete` is the page→SW envelope.

- `ProfileSchema = z.enum(['accessibility','standard','presenter'])`; export
  `DEFAULT_PROFILE = 'accessibility'` (a const the picker/background share, not a timing
  value).
- `SettingsSchema = z.object({ profile: ProfileSchema })`.
- `OnboardingStateSchema = z.object({ completed: z.boolean(), completedAt: z.number().optional(), version: z.number().int().nonnegative() })`; export `ONBOARDING_VERSION = 1`.
- `OnboardingCompleteSchema = z.object({ type: z.literal('onboardingComplete') })`.
- Names come from arch §3.2 / PRD FR-31; no synonyms. Re-export all from
  `packages/protocol/src/index.ts`.

Makes the two frozen contract tests (I1, I2) pass without editing them.

**Files:**
- Create: `packages/protocol/src/settings.ts`
- Modify: `packages/protocol/src/index.ts`
- Test: `packages/protocol/test/settings.test.ts` (parse/round-trip/default/reject-unknown
  for each schema)

## Task 2 — onboarding pure logic: `steps.ts`

DOM-free, `chrome.*`-free decision helpers, unit-tested in node (no browser globals):

- `cameraPresence(devices: {kind:string}[]): 'present' | 'absent'` — is there a `videoinput`.
- `cameraStep(status: CameraGrantStatus | null): 'ok' | 'needs-grant' | 'reroute'` —
  granted+persistent → `ok`; not-granted with a prior grant seen (Allow-this-time reverted)
  or denied → `reroute`; otherwise → `needs-grant`.
- `hostAccessMode(full: boolean): 'full' | 'restricted'`.
- `nextStep(state): Step` — orders Welcome → Camera → SiteAccess → Profile → Ready from the
  above outcomes; a dead-end (camera absent) parks on Camera.
- `defaultProfile(): Profile` → `DEFAULT_PROFILE`.

Types come from `@gesture/protocol` (Task 1). No `zod` import here (pure functions over
already-typed values).

**Files:**
- Create: `apps/extension/entrypoints/onboarding/steps.ts`
- Test: `apps/extension/entrypoints/onboarding/test/steps.test.ts`

## Task 3 — onboarding page + rule file

The full-tab React wizard (spec "The flow"). `App.tsx` owns all I/O; `steps.ts` (Task 2)
owns decisions. New `.claude/rules/onboarding.md` in the same commit (a changed boundary
changes its rule file, `CLAUDE.md §5`).

- `index.html` — semantic landmarks, `<title>`, mounts `main.tsx`.
- `main.tsx` — React mount.
- `App.tsx` — renders the five steps; `aria-live` status region for async waits; moves
  focus to each step heading on advance; every control a real `<button>`/`<a>`. I/O:
  `enumerateDevices` + `permissions.query` (readouts only, **no `getUserMedia`**); reads
  `storage.session.cameraGrantStatus` and subscribes to `onChanged`; opens
  `grant-camera.html` via `chrome.tabs.create`; `permissions.contains`/`request` for
  `<all_urls>`; writes `Settings` (sync) and `OnboardingState` (local) **after
  `Schema.parse`**; sends `OnboardingComplete` via `chrome.runtime.sendMessage`. Reads every
  stored blob back through its protocol schema before use.
- `.claude/rules/onboarding.md` — header-glob form (`# … — apps/extension/entrypoints/onboarding/**`).
  May depend on: React, `@gesture/protocol`, `wxt/browser` (`storage`/`runtime`/`tabs`/
  `permissions`), `navigator.mediaDevices.enumerateDevices` + `navigator.permissions`, DOM.
  Must never: `getUserMedia`, render/retain video/`VideoFrame`/`ImageBitmap`; network;
  secrets; gesture-timing logic or constant; `confirm()`; import `zod` directly. Every
  stored blob Zod-validated; consumed via `exports`, no deep imports.

WXT auto-discovers the entrypoint (build emits `onboarding.html`; no `wxt.config.ts`
change). `tsc`/lint/boundary-lint/unit tests green; never renders raw video; holds no
gesture-timing constant; no `confirm()`.

**Files:**
- Create: `apps/extension/entrypoints/onboarding/index.html`,
  `apps/extension/entrypoints/onboarding/main.tsx`,
  `apps/extension/entrypoints/onboarding/App.tsx`,
  `.claude/rules/onboarding.md`
- Test: covered by Task 2 (pure logic) and Task 5 (e2e); `App.tsx` is I/O-thin

## Task 4 — background: first-run trigger, onboarding gate, profile wiring

Make the flow real from the control plane. Keep the pure decisions in small helpers so they
are unit-testable without `chrome.*`.

- `runtime.onInstalled` (reason `install`) → open the onboarding tab
  (`tabs.create('/onboarding.html')`).
- Camera pre-check gate: while `OnboardingState.completed` is false, route to onboarding
  instead of starting the pump. Pure helper `shouldOpenOnboarding(state): boolean`.
- Read `Settings.profile` (Zod-validated) at startup and on `storage.onChanged`; feed the
  existing dispatcher `profile()` getter (replace the hardcoded `'standard'`). Pure helper
  `profileFromSettings(raw: unknown): Profile` (returns `DEFAULT_PROFILE` on absent/invalid).
- Handle the `OnboardingComplete` message (validated with `OnboardingCompleteSchema`): run
  the existing grant gate → start the pump.

Reads a non-secret `Settings` from `storage.sync` (allowed); validates every inbound
message (`.claude/rules/background.md`). No gesture-timing constant added — background only
selects the profile.

**Files:**
- Modify: `apps/extension/entrypoints/background.ts`,
  `apps/extension/entrypoints/background/dispatcher.ts` (widen `Profile` import to the
  protocol type; behavior unchanged for `standard`/`accessibility`)
- Create: `apps/extension/entrypoints/background/onboarding-gate.ts` (pure helpers:
  `shouldOpenOnboarding`, `profileFromSettings`)
- Test: `apps/extension/entrypoints/background/test/onboarding-gate.test.ts`

## Task 5 — Playwright e2e (fake webcam) + unhappy paths

`onboarding` project in `playwright.config.ts` (fake webcam, like the diagnostics/existing
projects). Covers the two roadmap Exit criteria and the required unhappy paths.

- **Happy path (E1/E2):** launch with the y4m fake webcam; walk Welcome → Camera (grant
  handoff; seed a persistent `cameraGrantStatus` in `storage.session` so the grant page is
  not required inside the harness, or drive it) → Profile (pick a profile) → Ready. Assert
  the onboarding page has **no** `<video>`/`<canvas>` (readouts only). Assert `Settings`
  round-trips through `chrome.storage.sync` and re-parses with `SettingsSchema` (**E2**).
  Assert `OnboardingState.completed` is written to `storage.local`. Capture
  `apps/extension/test-results/onboarding.png` for the owner's **E1** review.
- **Unhappy paths:** no `videoinput` present → dead-end copy renders, no hang, Recheck
  present; restricted `<all_urls>` → degraded copy + continue-limited/retry render;
  camera "Allow this time"/denied `CameraGrantStatus` → re-route guidance renders.
- **Accessibility path:** the whole happy path is completable by keyboard only (Tab/Enter,
  no pointer); each async step exposes an `aria-live` status region; focus lands on the new
  step heading on advance.

`tsc`/lint/boundary-lint green; E2 PASS; E1 owner-gated (steps in the journal).

**Files:**
- Create: `apps/extension/test/onboarding.e2e.ts`
- Modify: `apps/extension/playwright.config.ts` (add the `onboarding` project)
