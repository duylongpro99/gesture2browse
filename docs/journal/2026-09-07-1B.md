## Decisions / rulings
- **Weights `fetch` from the extension origin is not the offscreen "no network" boundary.** That boundary is remote/external network; loading a local web-accessible resource (same class as `models/hand_landmarker.task`) is authorized by spec §3. boundary-lint has no `fetch` rule. Cost if wrong: move the load to `main.ts` and transfer bytes into the worker — mechanical.
- **Adaptive-fps + restart-guard constants live offscreen, not in the FSM.** They are CPU-budget / lifecycle policy, not gesture timing (CLAUDE.md §2's single-owner rule is about gesture timing). Kept their identifiers free of `CLUTCH|COOLDOWN|HYSTERESIS|DWELL|DEBOUNCE` so the name-based boundary-lint rule 4 stays green.
- **Guard-refused restart must self-recover, not die.** The reviewer's Important finding: a refused restart originally left the pump permanently dead. Ruled for a bounded deferred-retry over the reviewer's minimal "tear down + document external recovery" — a camera that ends once inside the min-interval should not cost all gesture input until an extension reload.
- **`palmFacing` z-sign live confirmation is owner/real-camera work.** The helper uses the documented MediaPipe convention (z more negative = nearer camera) and is internally consistent; unit tests can't confirm it against a live camera (`.claude/rules/fixtures-and-tests.md`: real-camera checks are owner work). A sign flip is a one-line change and the gate is backward-compatible (`undefined` passes), so this is surfaced, not blocking.
